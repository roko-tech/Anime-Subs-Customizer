# ADR-001: Packaging and build reproducibility

- Status: accepted (2026-10-09)
- Deciders: maintainer

## Context

Users are not technical. Many have never installed Python, and the app's first impression decides whether they keep it. Today the only way to run the app is to install Python 3.10+, clone or download the code, run `pip install -r requirements.txt` and start `anime_subs_customizer.pyw`. The app needs Tk, customtkinter, Pillow, HarfBuzz (uharfbuzz), FreeType (freetype-py), pystray, pywin32, watchdog and chardet. Several of these load native code. The preview's Arabic shaping and the per-font size table both depend on HarfBuzz and FreeType actually loading. If they don't, the app falls back silently, and with a size preset on, a different size table would restyle a whole library.

## Options

1. **PyInstaller one-folder build** (`--windowed`, no UPX) with a committed spec.
2. PyInstaller one-file build. It unpacks to `%TEMP%` on every launch, leaves `_MEI*` folders behind after a crash, starts slower and draws more antivirus attention. A PyInstaller maintainer advises against it for distribution.
3. Nuitka. It compiles to C, needs a C toolchain (none is installed here) and doesn't set `sys.frozen`, which `app_root()` and `restart_app()` rely on. It's AGPL with a runtime exception since 4.x.
4. Embedded Python plus the source. This is fragile, and users would see `.py` files.

## Decision

- Use **PyInstaller one-folder, windowed, no UPX**. The build is defined by `AnimeSubsCustomizer.spec`. UPX is disabled explicitly, because PyInstaller applies it on its own whenever `upx.exe` is on PATH, as it is on the maintainer's machine through Scoop.
- **Exe name:** `AnimeSubsCustomizer.exe`, so command lines like `--quit` and `--self-test` need no quoting. Shortcuts show "Anime Subs Customizer".
- **Version:** `APP_VERSION` in `anime_subs/runtime.py` is the single source. The spec turns it into the exe's version resource, and the release workflow fails if the tag doesn't match it.
- **Build Python: 3.13.12** (x64, python.org/uv build). The frozen self-test passes on it at 250% DPI on the host and at 96 DPI in a clean Windows Sandbox. 3.12.9, the host's global Python, is too old (3.12's last Windows binary was 3.12.10).
- **Pinned build lock with hashes:** `requirements-lock.txt`, generated by `uv pip compile --generate-hashes` from `requirements.txt` + `requirements-build.in`. CI and the release build install with `--require-hashes`. `requirements.txt` stays a range file for developers.
- **chardet is pinned to 5.2.0** (LGPL-2.1+). The 7.x line is a relicensed rewrite whose relicensing the original author disputes, and its confidence scores no longer cross the app's 0.7 gate for legacy encodings. Golden decoding fixtures (no-BOM cp1256, cp1252, Shift-JIS, cp1251) are pinned in the tests, so changing the pin can't silently change decoding.
- **LGPL libraries stay replaceable:** `module_collection_mode={'pystray': 'py', 'chardet': 'py'}`, so they ship as plain `.py` files. python-bidi's `.pyd` is already a separate file.
- **Hidden imports:** `pystray._win32` and `watchdog.observers.read_directory_changes`. Both are imported by name at run time.
- **`--self-test` is the contract a build must pass.** It checks that HarfBuzz and FreeType loaded, the font list, the per-font size ratios, a preview render, an engine round trip (backup byte-identical, BOM and CRLF kept, signs untouched, DB record), string-table parity, the instance mutex and the watchdog backend. It writes a JSON report and exits 0 or 1 (2 on timeout).
- **Bootloader:** keep the stock bootloader. If VirusTotal flags it, build the bootloader from source (`pyinstaller/bootloader`, `waf all`) in CI and re-measure.
- **Nuitka:** no spike. There is no C toolchain on the build machine, and PyInstaller passed every check.

## Consequences

- No Python is needed on user machines. The app folder is about 55 MB (1,035 files) before FFmpeg.
- `sys.frozen` paths are exercised by `--self-test` on every release build: on the GitHub runner, and in the Sandbox before a release.
- A dependency upgrade means regenerating the lock and re-running the self-test. Dependabot opens PRs against the lock.

## Verification

- `scripts/build.ps1` runs: tests → freeze → `--self-test` of the exe → installer → portable ZIP → notices.
- Evidence: `.claude/launch/evidence/P05-pyinstaller` (host) and `G1-sandbox-selftest` (clean Sandbox, MOTW-stamped copy).
- The CI release job runs `--self-test` on the frozen exe and on the installed copy.

## Revisions after the checkpoint-2 critique

- `--self-test` also exercises a path over 260 characters. The exe's manifest declares `longPathAware`, and the self-test keeps that proven.
- `THIRD-PARTY-NOTICES.txt` (with the `LICENSES\` texts) ships **inside** the app folder and the portable ZIP as well as a release asset. It states that the LGPL Python libraries (chardet 5.2.0, pystray) are plain, replaceable `.py` files, and that python-bidi is a separate `.pyd`.
